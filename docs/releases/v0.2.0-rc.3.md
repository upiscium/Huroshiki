# Huroshiki v0.2.0-rc.3

Release date: 2026-08-02

## Highlights

- Added Packwiz-native CurseForge Install through the interactive TUI.
- Added verified cross-provider dependency equivalence for safe Modrinth and CurseForge
  artifact collapse.
- Improved bounded operation lifecycle handling and moved Update selection, dependency
  verification, and apply work off the Textual event loop.

## Packwiz-native CurseForge Install

- CurseForge Install uses Packwiz's interactive search path from the TUI; Huroshiki does not
  search the CurseForge API directly, and no API key is required.
- Search labels are display-only. Huroshiki performs an isolated numeric ID root-only probe for
  the selected root, then re-resolves and merges the complete dependency closure.
- Numeric IDs are required for noninteractive CLI, Profile, Template, and migration paths. These
  operations do not infer identity from names, slugs, URLs, filenames, or display labels.

## Verified cross-provider dependency equivalence

- Cross-provider candidates may collapse only when their declared SHA-256 values match, or when
  Packwiz Installer v0.5.14 materializes both candidates and their computed SHA-256 values match.
- If hashes do not match, equivalence requires an exact target-loader MOD ID-version set match.
  The declared SHA256, materialized SHA256, and exact target-loader MOD ID-version set are all
  verified as applicable.
- The resulting metadata uses the union of sides while retaining one metadata file and one JAR,
  with root provenance preserved. Explicit roots never collapse with one another.
- Explicit-root pairs and URL-provider candidates are never automatically collapsed. Names, slugs,
  display labels, and filenames are not evidence; version, loader, or MOD ID-set mismatches and
  verification failures remain conflicts and fail closed.

## Reliability and lifecycle changes

- Install and update preparation use one bounded lifecycle with cancellation checkpoints, an
  operation-wide deadline, and retained transaction state until cleanup is verified.
- PTY and resolver process cleanup is bounded and ownership-aware; incomplete termination retains
  the transaction rather than reporting false success.
- Update selection, dependency verification, and apply run off the Textual event loop, with
  navigation waiting for operation and cleanup completion.

## Breaking and behavioral changes

- Noninteractive CurseForge paths now accept numeric IDs only; names, slugs, URLs, and labels do
  not identify roots.
- Interactive CurseForge selection is Packwiz-native and uses labels only for display; identity
  comes from the root-only numeric ID probe.
- Dependency equivalence requires verified artifact evidence and complete target-loader identity
  matching; filenames or human-readable names are not evidence.

## Known limitations

- No live network-backed CurseForge install or cross-provider artifact collapse was executed as part of release verification.
- Mocked/local artifact tests cover it.

## Upgrade notes

- Existing interactive CurseForge workflows can use the TUI without configuring an API key.
- Automation and other noninteractive CurseForge workflows must provide a numeric project ID.
- Review cross-provider duplicate dependencies when upgrading; only verified equivalent artifacts
  are collapsed.

## Verification

Release verification includes focused mocked/local artifact and lifecycle tests, the complete
Python unit suite, and the repository's standard build and validation checks. The release checks
also verify the pinned Packwiz Installer v0.5.14 behavior and the interactive/noninteractive
identity rules.
