# Huroshiki v0.2.0-rc.5

Release date: 2026-08-03

## Highlights

- Packwiz now accepts `mode = "metadata:curseforge"` artifacts without a `download.url` when the
  candidate can be verified through the pinned Packwiz Installer.
- Resolver semantics, deadline ownership, and fail-closed verification remain unchanged.

## Packwiz-native CurseForge Install

- Fixed valid Packwiz-native `mode = "metadata:curseforge"` artifacts being rejected
  for lacking `download.url`.
- Delegated CurseForge metadata materialization mode to the pinned Packwiz Installer and
  preserved fail-closed safety for manual-download-only and unverifiable artifact flows.

## Packwiz-native CurseForge metadata artifact hotfix

`metadata:curseforge` artifacts are now accepted without requiring direct URLs because
download URLs are intentionally absent for metadata mode. Candidate project/file identity is
validated during metadata-aware resolution, and the candidate project identity is bound into
the metadata evidence path.

## Mode-aware materialization and validation

- Normalized isolated metadata materialization to always emit `side = "both"` for
  compatibility during verification closure checks.
- Delegated metadata mode handling to the pinned Packwiz Installer, preserving the existing
  noninteractive process lifecycle and timeout/cancellation controls.
- Kept URL mode behavior unchanged: bounded direct-download and loopback path transport
  continue to apply for explicit `download.url` candidates.
- Positive numeric project ID and positive file ID are validated before materialization in the
  metadata flow.

## Artifact verification and fail-closed behavior

- The produced artifact is still validated against the declared hash after Installer output.
- Existing SHA-256 and semantic JAR equivalence enforcement remains in force.
- Marker text for manual download requests remains recognized only as Installer-failure
  evidence for `metadata:curseforge`; marker text alone does not fail on success.
- Manual-download-only files remain fail-closed.

## Unchanged security and lifecycle behavior

- All noninteractive resolver lifecycle semantics, cancellation handling, orphaned descendant
  checks, bounded cleanup, and transaction ownership rules remain unchanged.
- No direct CurseForge API, API key transport, or guessed CDN URL handling was added for this
  release preparation.
- no API key is required.

## Known limitations

- No live network-backed CurseForge metadata materialization was performed in release
  verification.
- URL candidates still require explicit and deterministic `download.url` entries.
- Manually guessing or editing CurseForge CDN/URL values is not supported and remains out
  of scope for this release.

## Upgrade notes

- `metadata:curseforge` artifacts are now validated and materialized through Packwiz
  Installer without URL guessing.
- Upgrading from `v0.2.0-rc.4` does not require API-key credentials for release verification.

## Verification

Mocked and deterministic local tests cover regression paths for:

- `metadata:curseforge` materialization,
- missing URL handling,
- declared hash verification,
- `side = "both"` normalization,
- manual-download marker handling,
- fail-closed behavior,
- and absence of live network-backed CurseForge metadata materialization.
